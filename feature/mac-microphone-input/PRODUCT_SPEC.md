# Mac 麦克风语音输入

本规范定义 macOS 上显式启停所选麦克风送音的用户行为。此功能不要求连接遥控器、手机或网页。

- 连接页保留现有布局、输出设备和增益。新增物理输入设备选择及“用<设备名>说话”按钮，例如“用MacBook Pro 麦克风说话”“用AirPods Pro说话”；菜单栏入口使用同一文案。悬停提示必须为“可与遥控器麦克风同时使用”。
- 备用麦克风选择器始终显示；只有一个可用物理输入时仍保留下拉框。选择器只列出当前可用、可采集的物理输入，不显示未连接设备，也不显示“选择麦克风”占位项；没有可用输入时显示“无”、选择器禁用，并隐藏“用<设备名>说话”按钮。已保存的设备断开后，选择回退到系统默认物理输入或内置麦克风，不保留不可用项。
- 输入设备标签、设备名称、收音状态和启停按钮保持同一行。空间不足时截断设备名称，并通过悬停显示完整名称；状态和按钮保持完整。错误说明放在输入行下方，不缩小中文字号。
- 点击“用<设备名>说话”即开始持续采集所选物理麦克风并送入虚拟输出；启用后按钮为“停用<设备名>说话”，选择器禁用，系统显示麦克风正在使用。用户停用、系统挂起或设备/权限失败时停止采集并自然排空。蓝牙 HFP 首次启动可能需要数秒，期间保持“正在准备”。
- 右 Option、鼠标映射键及其按住/短按方式完全由豆包等输入工具处理，SayAll 不监听、不吞掉也不合成这些键。实体遥控器仍使用自己的 Fn 会话；两者共享同一虚拟麦克风音频出口。
- 系统休眠、锁屏或会话切换时必须释放正在采集的麦克风；最后一个系统挂起原因解除后，如果用户此前已启用 Mac 麦克风，则自动恢复持续采集，不要求用户停用再启用。
- macOS 因安全输入或超时临时禁用只读 event tap 时，待命监听必须周期检查并重新启用原 tap；不得在禁用回调内反复销毁和重建 tap，也不得要求用户停用再启用 Mac 麦克风。
- 对右 Option 等独立修饰键，任一 event tap 即使仍报告启用也可能静默停止投递；监听必须同时建立 HID 层与 Session 层的独立只读 tap，并读取系统 HID 按键状态，对三路边沿统一去重。短按切换模式单次录音最长 5 分钟，超时必须停止、排空并释放实体麦克风，不能因停止边沿丢失而无限采集。
- 启用音源时验证麦克风权限、所选输入设备和虚拟输出后开始持续采集；不需要输入监控或辅助功能权限，不以文本框状态作为启动条件。
- 当尚未保存选择时，默认读取 macOS 系统默认输入：如果它是可选物理设备，就使用该设备；如果它是虚拟、聚合或不可选设备，就回退到 Mac 内置麦克风。没有内置麦克风且系统默认不可选时，由用户在选择器可用设备中显式选择。保存选择后不持续跟随系统默认输入。设备丢失时停止并提示，同时把已保存选择回退到当前可用的默认物理输入，避免选择器出现不可用项。排除已识别的虚拟和聚合输入，避免自循环。
- 用户在选择器中选择设备后，SayAll 尝试将该设备设为 macOS 系统默认输入。选择器只提供当前具有输入通道的设备，不自动连接未连接的蓝牙设备。系统默认输入切换是尽力而为：失败时只记录日志，不显示“无法切换”等技术错误；本功能始终从所选设备直接收音，不依赖系统默认输入是否切换成功。启动和自动默认选择不修改系统默认输入。
- 音频只从所选物理麦克风进入当前 SayAll / MiRemoteV 2ch 或 BlackHole 2ch 虚拟输出。普通扬声器不能作为此功能的输出。本功能不修改系统默认输出，也不自动修改第三方工具设置。
- 首次明确启用音源时才请求麦克风权限；启用期间持续采集和送音，停用后释放。原始音频和文字历史继续遵循用户现有的显式保存设置。
- 使用已有已确认的工具按住/点按模式；无已确认绑定时显示当前配置的预期模式。选择音源的自定义组合键、键盘/鼠标触发键与遥控器语音键互不替代。原有遥控器、手机和网页的按键触发路径保持不变。
- 正常停止必须先停止采集准入，按序提交已接收的 PCM 与重采样尾部，再排空虚拟输出。不用 flush 丢弃正常尾音。
- 音频测试、系统挂起、长录音或不完整的会话切换仍拒绝本次启动。持续物理麦克风与实体遥控器、Apple Remote、Chromecast、手机或网页音频分别使用独立播放通道，由虚拟输出实时混合；远端会话开始或结束不得停止物理麦克风分支。
- 合盖或设备变化导致内置麦克风无音频、失效或采集失败时，只终止物理麦克风分支并记录可归因终态；遥控器分支、语音键生命周期和虚拟输出继续工作。未启用物理麦克风时，所有遥控器、手机和网页路径保持原行为。
- 切换前台应用或输入位置时保持送音，直到用户显式停止或发生设备、权限、系统生命周期异常。此功能不替用户选择输入位置。
- 权限拒绝、设备失效、采集失败、准备超时、系统休眠和退出均有可归因的终态。异常被迫中断必须记录 forced，不能报告为正常成功。所选设备已启动但持续没有 PCM 时，必须显示“所选麦克风没有音频”并记录 `no_audio`，不得以正常成功结束。

验证边界见 [测试手册](../../Testing/MacMicrophoneInput.md)。本地构建、模拟音频和截图不能证明真实文字上屏或硬件兼容。
